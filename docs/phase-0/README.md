# Phase 0 — Cadrage du projet MIMOUNI Gestion

Cette phase ne livre pas de fonctionnalité : elle fixe le cadre, les responsabilités et les critères d'acceptation du reste du projet. Les documents ci-dessous sont volontairement courts et opposables : chacun tient en une à trois pages et se relit à chaque fin de lot.

| [06 — Déploiement et recette](06-plan-de-deploiement-et-recette.md) | Mise en service, tests d'acceptation | Encadrement | à compléter |
| [07 — Reprise et exploitation](07-reprise-et-exploitation.md) | Sauvegardes, incidents, maintenance | Direction | à compléter |

## Règles de la phase 0

- Un document n'est valable que signé ou validé explicitement (nom et date en fin de document).
- Toute décision qui change le périmètre fait l'objet d'un avenant daté dans [02 — Périmètre](02-perimetre-et-hors-perimetre.md).
- Les documents sont stockés dans ce dépôt, versionnés avec le code : l'historique Git fait foi.
- Aucune donnée personnelle réelle n'est utilisée en recette : les jeux de démonstration suffisent.

## Sortie de phase 0

La phase 0 est terminée quand les sept documents sont validés, que le registre RGPD initial est saisi dans l'application et que la recette de [06](06-plan-de-deploiement-et-recette.md) est passée sur un environnement de test.
